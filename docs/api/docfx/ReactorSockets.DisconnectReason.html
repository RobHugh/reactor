Why a Peer's Session ended, defined and kept stable by this library rather than borrowed from a platform enumeration. Deliberately not shared with the Raw profile's CloseReason (ADR 0008): most of the members a Session needs are protocol vocabulary Raw can never produce, and a single shared enumeration would leave one profile documenting members it cannot emit.

public enum DisconnectReason

Fields

LocalClose = 0

The consumer called Close on this Peer.

VersionMismatch = 1

The two ends do not speak the same protocol version. The version match is exact — there is no negotiation, no lowest-common-version rule and no compatibility range — so this is produced both by the end that refused and by the end whose Hello was refused.

RemoteAtCapacity = 2

The remote end had no capacity Slot free for this Session and said so. Distinct from silence: a Reactor at capacity answers a Hello it received rather than dropping it, so the dialler learns the difference between "full" and "gone".

TransportFailed = 3

The underlying transport failed or ended before or during the handshake: a reset, a dial that could not connect, or a stream that closed before a full handshake record arrived. Distinct from every other member here because nothing about the protocol was at fault — the byte stream itself did not survive to carry it. Since issue #119, the same kind of failure on an established Peer no longer produces this reason at all — it moves the Peer to PeerInterrupted instead, because its identity and undelivered Messages are still worth holding for a Resume. This member now fires only for a Peer that never finished becoming one.

ProtocolViolation = 4

An established Peer's Message framing broke this profile's rules: a length prefix exceeding the announced MaxMessageSize, a length prefix of zero, a stream that ended before a length prefix or the Message body it named had fully arrived, or bytes arriving behind a Goodbye already received from that Peer (issue #93) — a Peer that announced it was leaving and then kept sending is contradicting its own announcement, so it is disconnected rather than believed. Distinct from TransportFailed: the byte stream itself survived long enough to carry the violation, and what is wrong is the bytes it carried rather than the transport underneath it. Distinct from PeerGoodbye, which is reserved for an ending that stayed clean to the last byte.

PeerGoodbye = 5

The remote Peer sent a Goodbye: it is ending the Session on purpose rather than failing (issue #23). Produced once whatever this end still held for it has finished flushing — immediately, if nothing was outstanding when the Goodbye arrived, or after the Closing Session it entered (PeerClosing) has drained.

LingerExpired = 6

An PeerInterrupted Peer's effective Linger — the value LingerNegotiated already reported at handshake (ADR 0011), the minimum of the two ends' announced Lingers — elapsed before the transport came back (issue #121). Linger, not the loss of the transport, is what closes an Interrupted Peer: the loss itself only produced PeerInterrupted (issue #119) and held the Peer's identity, counters and undelivered Messages open for a Resume. This member fires once that wait has run out, and is also what bounds a Close(PeerId) whose Goodbye can never reach a wire that no longer exists — without it, that Peer's retention would sit pending forever (issue #92). Distinct from TransportFailed, which means the byte stream never survived long enough to say anything at all — this means it survived, said nothing further within the time this end had promised to wait, and this end gave up on its own clock rather than being told to. Distinct from PeerGoodbye, which is an ending the remote announced on purpose while its transport still worked — this is an ending this end declares unilaterally, after silence, with no announcement possible because the transport that would have carried one is already gone.

RetentionGap = 7

A Resume's reported delivery counter named a Message position below this end's retention ring — the peer confirmed nothing further, but by the time it reconnected the bytes at its reported position had already been released to make room for newer ones (RetentionExhausted during the interruption, issue #120). Resuming anyway would deliver a stream with a hole in it, so this end closes instead (issue #130). Distinct from LingerExpired and TransportFailed because both of those are silent about why the Session ended — nothing was wrong with what either side said, only with how long the transport stayed reachable — while this one is a direct statement about what the peer said: its retention window was too small for the outage it just had. That makes the remedy actionable and specific — raise this end's retention capacity or its Linger, or both — in a way neither of those two members is. The mirror case, a Resume counter naming a Message this end never sent at all, is not this member: that is a protocol violation (ProtocolViolation), not a capacity question, because no amount of retention would have made a fabricated counter valid.

Remarks

Explicit values throughout, house style since RawLinkLegality (PR #70): a member is added at the end with the next free number, never inserted, so a value a consumer has already persisted keeps its meaning across a library upgrade.

Every place this library maps something else onto a DisconnectReason — a wire ReactorSockets.Session.RefusalReason, a malformed-framing outcome, a Goodbye control record — states that mapping as its own table with a discard arm that refuses rather than permits, the same house rule RawLinkLegality follows: an input this library does not recognise fails closed instead of being guessed at.
