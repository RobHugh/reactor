MaxMessageSize

The largest Message, in bytes, this Reactor will accept or deliver. Required: it is a statement about the consumer's own protocol that nothing here can derive. It is also the knob that multiplies this profile's memory bill in more than one direction — the class remarks on DatagramSessionOptions say what it floors and what raising it costs.

public required int MaxMessageSize { get; init; }

Property Value

int

Remarks

Announced to the peer at the handshake precisely so an oversized claim can be refused before this end holds anything for it: a declared Fragment fragmentCount larger than this Reactor's receive window (ResolvedReceiveWindowFragments) is closed on its first Fragment, before any receive-window slot or Fragment-group bookkeeping exists for it. The bound is the window rather than ReceiveWindowFloor alone, because the floor is computed from this end's own ResolvedFragmentSize and fragment size is unilateral and per-direction (ADR 0004): a conforming peer with a smaller fragment size legally cuts the same, within-limit Message into more Fragments than the floor. ReactorSockets.DatagramSessionOptions.Validate() already requires the window to be at least the floor, so a set at exactly this value is always admitted.
