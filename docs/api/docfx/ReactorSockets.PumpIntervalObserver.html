Measures the interval between consecutive Pump() calls from monotonic TimeProvider timestamps. This is what makes the re-dial schedule's initial delay (ReactorSockets.Session.RedialSchedule) derived rather than invented: a retry sooner than the next Pump cannot happen, so the next Pump is the floor, and the only way to know that floor is to watch how often Pump is actually called.

Remarks

Public for the same reason ReactorSockets.Session.RedialSchedule is (ADR 0015): a test pins this behaviour by constructing one directly against a substituted TimeProvider and calling Observe() the same way a Reactor's own Pump would, with no InternalsVisibleTo and no interface invented for the purpose.

Only GetTimestamp() and GetElapsedTime(long, long) are ever consulted, never GetUtcNow — the monotonic-only discipline ADR 0002 states for every timer this library owns, applied here for the first time. A consumer's own loop is irregular by construction (the library owns no threads, ADR 0002), so every Observe() call replaces Interval outright rather than folding it into a running average: the most recent cadence is what a schedule should track, not a stale first reading a later, faster or slower loop has already left behind.
