ReactorSockets

Enum DiagnosticId

Namespace
ReactorSockets
Assembly
ReactorSockets.dll

A closed, permanent enumeration of diagnostic causes with explicit values in reserved blocks — common 1-99, Raw 100-199, datagram session 200-299, stream session 300-399 (ADR 0013) — so a future insertion cannot silently renumber an id a consumer has persisted. There is no None or Unknown member and zero is never used: every DiagnosticRecord has a cause by construction.

public enum DiagnosticId

Fields

AdmissionCapReached = 1

The configured admission cap was hit this Pump with work still waiting to be admitted. No subject. Value0 is the cap, Value1 is the count of Admissions declined, counted as the Reactor's counters count them: once per declining where the work waits out of reach — a listening Link or bound endpoint with a pending connection it left in the OS backlog, never the number of connections left there, a depth unknowable without accepting — and once per piece of work where the Reactor was holding it, whether it then waits or is Discarded.

ArenaExhausted = 2

The frame arena had no room left for a request, regardless of the read-share escape. Subject is the Link that made the request on Raw, and the Peer whose Message could not be reserved on either session profile (ADR 0014). Value0 is the bytes requested, Value1 is the arena's bytes free at the moment of the request.

CapacityExhausted = 3

Every capacity slot was occupied this Pump with work still waiting to be admitted — a different exhaustion from AdmissionCapReached, reachable because the admission cap can be configured above Capacity. No subject. Value0 is the capacity, Value1 is the count of Admissions declined, counted the same way and with the same limit as AdmissionCapReached's.

LinkFailed = 100

A registered Link failed and closed. Subject is the Link. Value0 carries the platform SocketError as its underlying integer value; Value1 is unused.

DestinationUnreachable = 101

An ICMP port-unreachable (or platform equivalent) was reported for a send. Subject is the Link. Value0 carries the platform SocketError as its underlying integer value; Value1 is unused.

DatagramTruncated = 102

A datagram exceeded the Reactor's scratch buffer and was truncated. Subject is the claimed Source. Value0 is the scratch buffer size in bytes; Value1 is unused.

DatagramMalformed = 200

A datagram was discarded because nothing in it could be attributed to a Peer: wrong length, an unknown control type, a body the declared type cannot fill, padding that was not zero, a session id naming no Session, or a well-formed control reply — a Cookie, an Accept, a Refusal — matching no dial this Reactor is waiting on. That last case is not a parse failure, but it is the same thing to a consumer: bytes arrived, named nobody, and went nowhere. Subject is the claimed Source. Value0 is the bytes received; Value1 is unused.

A remote can produce this at will by sending rubbish, which is exactly why it is a Diagnostic and never an Event: the event stream is the consumer's protocol, and an unauthenticated stranger must not be able to write to it. Warn rather than Error for the same reason — nothing is wrong with this Reactor.

CookieRejected = 201

A Hello carried a cookie this Reactor did not mint, or minted too long ago: a forged or corrupted authenticator, a cookie replayed from a different source address, or one from an epoch older than the previous. Subject is the claimed Source. Value0 is the epoch the cookie offered; Value1 is the epoch current at the moment it was checked.

Warn, never Error: a cookie arriving one epoch after it was minted is the mechanism working, and a Reactor visible to the internet will see forged ones continuously. Raising this to Error would train a consumer to ignore Error.

VersionRefused = 202

A cookie-validated Hello offered a protocol version this Reactor does not speak, and was refused. Subject is the claimed Source. Value0 is the version offered; Value1 is the version this Reactor requires.

Emitted only for a Hello that passed the cookie check, because that is the only Hello a Reactor answers at all — a bare Hello is answered with a Cookie and nothing else, whatever version it claimed.

FragmentSetAbandoned = 203

A Fragment set for an established Peer was abandoned before it ever completed. Subject is the Peer, not the claimed Source: an incomplete set belongs to the Session that was receiving it, not to a bare source address. Value0 is the number of fragments actually held for the set at the moment it was abandoned; Value1 is the number the set's own metadata declared it would need. Held against expected is the pair a consumer can act on — one of forty held is a path dropping almost everything of that size, thirty-nine of forty is ordinary loss on a set that was nearly there, and the two want different responses.

Warn, not Error: nothing local is broken, an abandoned set is loss on a lossy transport working as designed, and the level's job is to answer whether a consumer wants to see this, not whether this Reactor is at fault.

RetransmissionTimerBackedOff = 204

This Peer's ReactorSockets.RetransmissionTimer backed off: a Pump's expiry sweep (ReactorSockets.Session.OutstandingReliableSequences.CollectExpired(ReactorSockets.Session.PacketRecordMode)) found at least one overdue sequence on either reliable Space, so ReactorSockets.RetransmissionTimer.BackOff() was called once for the Peer and every sequence the sweep reported re-armed at the single resulting RTO. Subject is the Peer. Value0 is the new RTO in milliseconds — EffectiveTimeout(TimeSpan, TimeSpan) at the moment of the backoff; Value1 is ReactorSockets.RetransmissionTimer.ConsecutiveBackoffs after this backoff.

Trace, not Warn: this is protocol machinery working correctly, not a fault. A lossy path emits it continuously — every Pump that finds an overdue sequence backs off again — and raising it above Trace would train a consumer to ignore the level it sits at.

OversizedFragmentSet = 205

An established Peer's Fragment declared a fragmentCount larger than this Reactor's own receive window could ever hold, and the Session was closed with ProtocolViolation on that Fragment's first appearance, before any receive-window slot or Fragment-group bookkeeping was created for its set. Subject is the Peer. Value0 is the declared fragmentCount; Value1 is the largest legal count this Reactor's ResolvedReceiveWindowFragments allows.

Warn, for the same reason as DatagramMalformed: a remote can produce this at will by lying about how many Fragments a Message needs.

UnreliableFragment = 206

A packet record carried the fragment shape in one of the two unreliable modes, which ADR 0004 forbids — you may only fragment what you can retransmit — and the read failed outright, taking the whole Datagram with it. Subject is the claimed Source, not the Peer, matching the DatagramMalformed that is raised alongside it: a discarded Datagram is never attributed to the Session it named, and no byte of it is counted against that Peer. Value0 is the mode the record claimed, as the two mode bits' wire value — 0 for Unreliable, 1 for UnreliableSequenced; Value1 is unused.

Warn, for the same reason as DatagramMalformed: a remote can produce this at will, and nothing is wrong with this Reactor.

Distinct from DatagramMalformed rather than folded into it because the two say different things to a consumer. A malformed Datagram is rubbish from anywhere; this one is well-formed at every level but the rule, which means the sender is running a build that fragments in modes this profile does not — a misconfiguration a consumer can act on, and the send path already refuses to produce.

OversizedMessage = 207

A completed Message, whole or reassembled from its Fragments, was larger than this Reactor's own MaxMessageSize and was discarded instead of delivered. Subject is the Peer. Value0 is the Message's length in bytes; Value1 is this Reactor's MaxMessageSize. The Session stays open, and a discarded reliable Message stays acknowledged, so the far end does not resend it and later Messages are unaffected.

Warn, for the same reason as DatagramMalformed: a remote can produce this at will, and nothing is wrong with this Reactor.

AddressPeerLimitReached = 208

A verified handshake, or on the stream profile an accepted connection, was refused because its address already holds MaxPeersPerAddress or MaxPeersPerAddress accepted Peers while other capacity Slots were free. On the stream profile it is also logged when an accepted connection is closed before its first handshake record arrives, because its address already has that many other connections held waiting for theirs. Subject is the claimed Source. Value0 is the limit; Value1 is the prefix length the address was counted by: 32 for IPv4, and PeerLimitIPv6PrefixLength or PeerLimitIPv6PrefixLength for IPv6, so every address in that prefix shares the limit. One record per refusal, because it names the address and the admission cap already bounds how many refusals a Pump can make. A full Reactor reports CapacityExhausted on the datagram profile and PeerRefused on the stream profile instead.

Warn: a remote can produce this at will, and a consumer can act on it by raising the limit if the address is a NAT or proxy, or by blocking it if it is not. Defined by the datagram profile and shared by the stream profile, because it is one condition (ADR 0020).

DatagramReadLimitReached = 209

A Pump made MaxDatagramsPerPump reads on one bound socket and stopped. What was left, if anything, waits for a later Pump. No subject. Value0 is the limit; Value1 is the socket's index in BoundEndpoints. At most one record per bound socket per Pump.

Warn: a remote can produce this at will, and it names a configured bound a consumer can act on. A queued socket error spends a read, so not every read was a datagram. The socket's queue depth cannot be read past queued errors, so a Pump that read exactly the last queued datagram also reports this.

OversizedFragment = 210

An established Peer's reliable Fragment carried more payload bytes than this Reactor's own ResolvedFragmentSize, and the Session was closed with ProtocolViolation before anything in that Datagram was acknowledged (ADR 0024). Subject is the Peer. Value0 is the Fragment's payload length in bytes; Value1 is this Reactor's ResolvedFragmentSize.

Warn, for the same reason as DatagramMalformed: a remote can produce this at will. The handshake announces the size, so a conforming peer never sends a wider Fragment, and the width and the size say which end is misbuilt.

PeerRefused = 300

A dialler was refused in-protocol during the stream handshake, either because it announced a different protocol version or because every capacity Slot was occupied. Subject is the claimed Source: at refusal time there is no Peer, only a claimed origin. For a capacity refusal, Value0 is this Reactor's capacity and Value1 is unused. For a version refusal, Value0 is the version offered and Value1 is the version this Reactor requires.

Info, not Warn: a version mismatch on an upgrade and an ordinary burst at capacity are both routine, expected outcomes of running this profile, not conditions a consumer needs to act on.

LingerNegotiated = 301

A Session established — on either profile, stream or datagram — and the two ends' announced Linger values were negotiated to their minimum (ADR 0011). Subject is the newly established Peer. Value0 is this end's own Linger in milliseconds; Value1 is the effective (minimum) Linger in milliseconds.

MalformedFraming = 302

An established Peer's Message framing broke this profile's rules and the Session was closed with ProtocolViolation: an oversized or zero-length prefix, or a stream that ended before a prefix or the Message body it named had fully arrived. Subject is the Peer. Value0 is the offending length prefix — 0 for a truncation, where no full prefix was ever read; Value1 is this Reactor's own MaxMessageSize.

Warn: a remote can produce this at will by sending malformed bytes, which is exactly why the Session ends rather than throws, and why this is a Diagnostic rather than an Event on the consumer's own stream.

DataAfterGoodbye = 303

An established Peer sent Message bytes after its own Goodbye had already been received, and the Session was closed with ProtocolViolation. Subject is the Peer. Carries no claimed length — ReactorSockets.Session.MessageFramingLegality reaches this outcome before ever reading a prefix, so there is nothing to report but the contradiction itself. Value0 and Value1 are unused.

Warn, for the same reason as MalformedFraming: a remote can produce this at will by ignoring the Goodbye it just sent.

ResumeMatched = 304

A connection presenting a valid resume secret was matched onto the Interrupted Peer whose Slot was reserving the Session it named, and that Session continued over the replacement transport rather than a new one being established (ADR 0011). Subject is the resumed Peer — the same PeerId, generation included, the Session had before the interruption, since nothing about a Peer's identity is renewed by a Resume. Value0 is the number of retained outbound bytes the match rewound to the counter the Resume reported; Value1 is unused. On the datagram profile it is logged when a Resume control datagram matches the Peer on the accepting end (session id and secret), when an Interrupted accepting end receives a well-formed data Datagram for the Session from the exact address and port it sends to, and when an Interrupted dialling end that has sent a Resume hears its session again. Nothing is rewound, because retransmission already re-sends anything unacknowledged, so Value0 is 0 and Value1 is unused.

Info: a reconnection is the outcome reserving a Slot exists to produce, not a condition a consumer needs to act on.

Shared with the datagram session profile rather than duplicated in the datagram block, as are LingerNegotiated and ResumeUnmatched (ADR 0020).

Numbered 304 because 302 and 303 belong to MalformedFraming and DataAfterGoodbye, and a value published in a closed permanent enum is never renumbered.

ResumeUnmatched = 305

A connection claiming an existing Session was refused rather than resumed. Subject is the claimed Source: a claim that is not matched comes from a party that is by construction not a Peer, so there is no Peer to name, only a claimed origin. Value0 is the number of Interrupted Peers whose reservations the claim was checked against — 0 means nothing was being held at all, which is the reconfiguration path where a once-valid secret arrives after its Linger expired. Value1 is the wire record type the claim arrived as: 3 for a Resume whose secret matched no held Peer, and 1 for a Hello presenting a secret that did match, which re-announces the parameters a Resume has no field for and is refused as a protocol violation.

Warn rather than the Info a version mismatch or a capacity refusal carries: those are routine outcomes of running this profile and a wrong secret is not.

"Unmatched" names the outcome, not the comparison: the claim was not matched onto a Session. The Hello case reaches here having found the secret it announced, and is refused anyway because the record it arrived in re-announces parameters — Value1 is what tells the two apart.

Value0 is reported to this end's own Sink and never to the wire: a refused party is closed on without being told anything, so it learns neither the count nor which of the three refusals it met.

The datagram profile reports a Resume control datagram the same way, with Value1 6 (the Resume control type, DatagramControlType.Resume). Value0 is 0 when the target session id names no Peer the Reactor holds, or names a dialled Peer (never a Resume target, since only the dialling end sends Resume), and 1 when it names a Peer but the presented secret does not equal the one that Peer issued.

RedialAttempted = 306

A dialling-side Peer began a fresh re-dial attempt after its transport was lost (ADR 0011). Subject is the Peer. Value0 is the attempt number, starting at 1 and rising by one per attempt; Value1 is the delay in milliseconds this attempt actually waited before dialling — the jittered figure ReactorSockets.Session.RedialSchedule.NextDelay() drew, so what actually elapsed is observable rather than only the computed figure before jitter.

Info: a re-dial is the ordinary behaviour of a dialling Peer that lost its transport, not a condition a consumer needs to act on.

RedialFailed = 307

A re-dial attempt could not connect, or connected and ended before the listener confirmed the Resume (ADR 0011). Subject is the Peer, which this never closes — it stays Interrupted and waits out the schedule's next delay, leaving Linger, not an attempt count, the only thing that ever closes it. Value0 carries the platform SocketError as its underlying integer value: for a connection that ended before confirmation it is Disconnecting for an end of stream, or the read's error. It is TimedOut when the listener did not answer within the receive-idle deadline, and SocketError when the Resume record could not be sent. Value1 is the attempt number that failed.

Info rather than Warn: under this profile's premise a failed reconnection attempt is an ordinary, expected outcome, and raising it to Warn would train a consumer to ignore Warn.

DeliveryCounterRefused = 308

An established Peer's delivery-counter record claimed to have received more Messages than this end has ever sent it, and the Session was closed with ProtocolViolation — the peer is confirming Messages this end never queued, rather than merely repeating a count it already reported. Subject is the Peer. Value0 is the claimed cumulative count; Value1 is the count of Messages (and, if this end's own Goodbye has already been queued for this Peer, that too) this end has actually appended to this Peer's retention — the largest count a legitimate confirmation could ever sit at or below.

Warn, for the same reason as MalformedFraming: a remote can produce this at will by inflating its own counter.

Numbered 308 rather than the next free 304: ADR 0013's roster reserves 304-307 for the Resume and redial Diagnostics (ResumeMatched and ResumeUnmatched, then RedialAttempted and RedialFailed), and a value published in a closed permanent enum cannot be moved later to make room.

PendingAdmissionExpired = 309

A connection the stream profile accepted sent no whole first handshake record within this end's SendIdleInterval × MissedHeartbeats of being accepted, and was closed with nothing sent. Subject is the claimed Source. Value0 is the bytes of that record it had sent, 0 to 40; Value1 is the deadline in milliseconds.

Warn: a remote can produce this at will by connecting and sending nothing, and a consumer can act on it by blocking the address or, if conforming diallers are being closed, by raising SendIdleInterval. One record per connection, because it names the address. The deadline is fixed at accept, so bytes that arrive do not extend it. At most Capacity connections are held, so no more records than that are logged in one Pump.

PendingAdmissionLimitReached = 310

A stream Reactor already held Capacity accepted connections waiting for their first handshake record, so it accepted no more that Pump and left the rest in the OS backlog. No subject. Value0 is the limit, which is the capacity; Value1 is the count of Admissions declined, counted as AdmissionCapReached's are: once per listening Link left with a pending connection.

Warn: a remote can produce this at will by opening connections and sending nothing. One record per Pump. The held connections close at their deadline (PendingAdmissionExpired), so the backlog is accepted again within that time.

Remarks

Supported Sink style: range-check the blocks. The enum grows inside its blocks, so a Sink that classifies an id by the block it sits in, or that switches on members it cares about with a default arm for the rest, keeps working when a member is added. A Sink whose switch assumes it lists every member is not supported: the next additive release breaks it.

A block names the profile that defined a condition, not the profile that emitted a record (ADR 0020). LingerNegotiated, ResumeMatched and ResumeUnmatched sit in the stream block and are emitted by the datagram session profile too, because each is one condition and a member names a condition. A Raw-only Sink's range check over 100-199 is exact, since nothing outside Raw shares that block. A Sink that needs to know which profile emitted a record knows which Reactor it was given to.

Each member's documentation is the authority on its subject and value slots. ADR 0013's roster table is the one place to check them side by side and is kept in step with these docs.
