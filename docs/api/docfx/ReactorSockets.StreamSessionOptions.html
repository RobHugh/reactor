Remarks

A knob carries a default only when that default is derived — from machinery this library owns, from another knob, or from a citable standard. A value that trades the consumer's own resources against their own traffic, and that nothing in this library can derive, is required with no default: MaxMessageSize, RetentionBytes, SendIdleInterval and Linger are all of that kind, and so is Capacity. Guessing any of them would be guessing at the consumer's application.

There is no cookie, no ack, no sequence space, no fragment and no RTO here: TCP already provides what those were built for, so a knob to configure one would have nothing under it.

The memory bill. A Reactor built from these options holds at most Capacity × (RetentionBytes + receive buffer + Message-boundary ring) bytes, all of it per Peer and none of it shared, so a Send on a healthy Peer never fails because of somebody else's traffic. Retention and the ring are allocated at construction and each receive buffer when its Peer takes a Slot, so the bound has no traffic term. The retention line is buffered twice over — once in our retention, once again in the kernel's own send buffer for the socket — so a stream Peer's real footprint is this bound plus whatever the OS is holding, and the OS's half is not fully ours to control. The third line is what lets retention be released by what the peer has confirmed receiving rather than by what the local kernel merely accepted, and is driven by RetentionBytes too: one uint per Message that could be outstanding in a Peer's retention region at once, which this profile's four-byte length prefix bounds at roughly one entry per four retained bytes, so it costs about as much as retention itself.

MaxMessageSize appears in three places at once: announced to the remote as a receive limit, flooring the receive buffer, and flooring RetentionBytes. It is therefore the one knob whose careless enlargement multiplies memory in two directions rather than one.

Nagle is off on every stream Session socket and there is no knob to turn it on (ADR 0011): this library batches by writing everything queued since the last Pump once, so a latency measurement measures the consumer's Pump cadence, not TCP's acknowledgement clock.

Every check below is deterministic and entirely the caller's, so failures throw at construction — ArgumentOutOfRangeException for a single bad value and ArgumentException for a combination that cannot work — rather than being reported through a Result.

Properties

BoundaryRingBudgetBytes

The Message-boundary ring line of the memory bill in bytes: one uint (4 bytes) per entry in ReactorSockets.StreamSessionOptions.BoundaryRingEntriesPerPeer, across every Peer, reported the same way as the other two lines. This is what makes releasing retention by what the peer confirmed receiving possible at all — see the class remarks.

Endpoints

The endpoints to bind at construction, in the order supplied; possibly empty. Declared once and never rebound (ADR 0014) — a Session's addresses are part of what it is, not something it acquires later. A consumer addresses Peers, never the sockets this profile binds, so binding returns no identity: an empty set means dial-only, a meaningful configuration rather than a hole, and there is no rebind — a Reactor that must listen elsewhere is a new Reactor. Provenance: empty is the absence of a declaration, not a chosen address — a dial's local port is the one TCP's connect binds implicitly.

Entropy

The entropy the resume secret is drawn from. A construction knob in ADR 0011's sense — the consumer's own resource, and a consumer with a hardware source or a policy about which generator may be used is entitled to supply it. It carries a default only because that default is derived rather than guessed. Provenance: the platform's own CSPRNG.

Linger

How long a closing Session stays alive to retransmit its Goodbye and absorb what is still in flight. Required, for the same reason as SendIdleInterval: it trades a prompt teardown against a clean one. At most 2^32 - 1 milliseconds (about 49.7 days), the most a handshake may announce.

MaxMessageSize

The largest Message, in bytes, this Reactor will accept or deliver. Required: it is a statement about the consumer's own protocol that nothing here can derive. It is also announced to the remote as a receive limit, and floors both the receive buffer and RetentionBytes — an arena that cannot hold one maximum Message could never deliver one.

MaxPeersPerAddress

The most accepted Peers one address may hold at once (issue #452), so one reachable address cannot occupy every capacity Slot. Defaults to ResolvedMaxPeersPerAddress, one fewer than Capacity. Provenance: derived from capacity, as the largest limit that still keeps one address from holding every Slot (ADR 0014). How many Peers legitimately share an address depends on the NATs and proxies in front of this Reactor, so set it lower when strangers can reach it. At least 1. A value of Capacity or above sets no limit, which is what the default is at a capacity of 1.

MissedHeartbeats

How many consecutive heartbeat intervals may pass in silence before a Peer is declared gone. Defaults to 3. Provenance: RFC 4271's hold time, three times the keepalive interval. Must be at least 2, because a count of 1 makes a single lost heartbeat fatal, and in .NET the stall that produces it is as ordinary as a collection pause.

PeerLimitIPv6PrefixLength

How many leading bits of an IPv6 address form the key for MaxPeersPerAddress, so every address in one prefix shares one limit. Defaults to ResolvedPeerLimitIPv6PrefixLength, 64. Provenance: RFC 4291 §2.5.1 fixes the interface identifier of a unicast address at 64 bits, so a /64 is one link (ADR 0014). From 1 to 128. A value of 128 counts each address on its own.

Reactor

The shared L0 budget: capacity, admission cap, arena size, time source and Diagnostic Sink. Required — a Reactor cannot be built without one, and its Capacity has no default of its own.

ReceiveBudgetBytes

The receive line of the memory bill in bytes, as a long so that a combination too large to allocate is a value this can report rather than an overflow it silently wraps through.

ReceiveBufferFloor

The floor both RetentionBytes and the receive buffer are held to: one maximum Message plus its length prefix.

ReceiveBufferSize

The bytes held per Peer for an incoming, not-yet-complete Message. Defaults to MaxMessageSize plus the 4-byte length prefix. Provenance: derived from MaxMessageSize — its own floor, since that is exactly one incomplete maximum Message and nothing narrower could ever hold one.

ResolvedMaxPeersPerAddress

The resolved per-address limit: MaxPeersPerAddress if set, otherwise one fewer than Capacity, and at least 1.

ResolvedMissedHeartbeats

The resolved missed-heartbeat count: MissedHeartbeats if set, otherwise 3.

ResolvedPeerLimitIPv6PrefixLength

The resolved IPv6 grouping length: PeerLimitIPv6PrefixLength if set, otherwise 64.

ResolvedReceiveBufferSize

The resolved receive buffer: ReceiveBufferSize if set, otherwise ReceiveBufferFloor.

RetentionBytes

The bytes retained per Peer for the send path — retention is the send path (ADR 0011): a Send frames the Message once and appends it to this Peer's ring, and what reaches the socket is a copy from it. Required: this is the consumer trading their memory against their tolerance for a stalled Peer, and the right answer depends on their traffic, not on anything here. Must be at least MaxMessageSize plus the 4-byte length prefix, or a single maximum Message could never be retained.

SendBudgetBytes

The send line of the memory bill in bytes, reported the same way.

SendBufferSize

SO_SNDBUF for every Peer socket this Reactor accepts or dials, or null — the default — for the OS default and its own autotuning. This is the kernel's send queue, not RetentionBytes: retention is what this end holds until the peer confirms receipt, while this bounds how much the kernel will absorb from a flush before a write reports it would block and the bytes stay in retention, unsent. Unset, the two are unrelated in practice on Linux, whose send autotuning will absorb megabytes against a peer that has stopped reading; set, a consumer who needs transport backpressure to reach their own flow control at a known point can put it there. Provenance: unset leaves the OS's own default and autotuning in place, so the library chooses nothing.

SendIdleInterval

How long a Session may go without sending before it sends a heartbeat instead. Required: shorter costs bandwidth on an idle link, longer costs time to notice a dead Peer, and only the consumer knows which they would rather spend. At most 2^32 - 1 milliseconds (about 49.7 days), the most a handshake may announce.
