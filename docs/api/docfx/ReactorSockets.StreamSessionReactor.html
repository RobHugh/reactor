The stream Session profile (ADR 0010): Sessions established over TCP, addressed as Peers, delivering u32 length-prefixed Messages rather than the byte runs the transport gives. Construction validates StreamSessionOptions and its allocation bill and binds the declared endpoint set; each Peer is carried through the handshake to an established Session. Each established Peer reassembles Messages in its own persistent receive buffer and delivers each whole one as a MessageReceived event copied into the shared frame arena.

Remarks

There is no cookie, no ack, no sequence space, no fragment and no RTO in this profile: TCP already provides what those were built for. The datagram Session protocol is deliberately not carried over TCP, because that would put retransmission on top of retransmission.

Send timing (ADR 0011). Nagle (TCP_NODELAY) is off, unconditionally, on every stream Session socket — it is not a knob on StreamSessionOptions and cannot be turned back on. In its place, every Send(PeerId, ReadOnlySpan<byte>) queued since the last Pump() is written to the wire together, once, by that Pump() call: batching we do ourselves, on our own schedule, rather than the connection's delayed acknowledgements deciding when a small Message may leave. That is a better version of what Nagle exists for, without Nagle's cost — a small Message waiting up to a round trip behind outstanding data — so a consumer measuring latency needs to know which of the two is doing the batching: theirs, by calling Pump() less often, or ours, always.

Constructors

StreamSessionReactor(StreamSessionOptions)

Validates options — every knob and cross-check, then the frame arena's floor — before anything is allocated or bound, then binds every declared endpoint in the order supplied. A bind that fails throws here, naming the endpoint: binding is part of what this Reactor is, so there is no half-built Reactor to hand back.

Properties

BoundEndpoints

The endpoints this Reactor is bound to right now, in the order they were declared. A snapshot: it answers what is bound, and there is no member that binds another — there is no rebinding (ADR 0014), and unlike the datagram profile a stream dial never binds a wildcard socket of its own, since TCP's own connect already binds an ephemeral local port implicitly.

Methods

Close(PeerId)

Announces this end is ending the Session with peer on purpose: attempts to append a Goodbye control record to whatever this Peer's retention region already holds, so it is the last thing flushed and everything queued before it is delivered first, then forbids any further Send(PeerId, ReadOnlySpan<byte>) to it. If retention has no room for it yet, the attempt is retried on every later Pump (ReactorSockets.StreamSessionReactor.RetryGoodbyeAppends()) until it commits — Close(PeerId) must never leave the far end open indefinitely because the Goodbye it promised was silently dropped, and this end never closes itself locally until its own Goodbye has actually been appended and flushed. The PeerClosed carrying LocalClose is queued once that flush fully drains — immediately, on a later Pump, if nothing was queued when Close(PeerId) was called, or after however many Pumps a short write (or a retention append retry) takes to carry everything already retained plus the Goodbye itself. Idempotent: a stale PeerId, or a Peer already closing, is a no-op — a Peer closing under a caller, or a caller that closes the same Peer twice, is an ordinary race rather than a programmer error.

Connect(IPEndPoint)

Begins a Session with destination, returning the PeerId that will address it. The Peer occupies a capacity Slot from this moment, exactly as a dialling Link does in RawReactor: the handshake is work this Reactor is holding, and pretending otherwise would let a consumer dial past capacity and discover it only on the far side of a round trip. PeerConnected or PeerClosed resolves it on a later Pump. A dial that has not established one Linger after this call closes with TransportFailed, whether its TCP connect is still pending or the far end connected and sent no handshake record.

CountersOf(PeerId)

A point-in-time snapshot of one Peer's counters (ADR 0013). Throws if the Peer is not open. Mirrors CountersOf(LinkId)'s shape for the Raw profile.

Dispose()

Releases every socket this Reactor bound or accepted. A Reactor owns every socket it bound, so a consumer that drops one without disposing it leaks those sockets until each Socket's finalizer runs. No PeerClosed events are queued: nothing can drain a disposed Reactor. Idempotent; every other member throws ObjectDisposedException afterwards.

Drain()

Drains every event produced this Frame — since the last Pump() — in the order it was produced.

Pump()

One synchronous advance: records this call's arrival against the last one (ReactorSockets.StreamSessionReactor.ObservedPumpInterval) before anything else, then wipes the previous Frame's events — which is also the moment a Peer still PeerClosing only because the last Frame's Messages had not been drained past yet becomes eligible to close (ReactorSockets.StreamSessionReactor.RetryPeersPendingClose()) — then admits ready connections, advances every in-flight dial and reads whatever bound socket is ready right now, running the handshake for everything that arrived. Every Peer whose received count advanced somewhere in that work — this Frame's own reads, or a held-back Message finally delivered by ReactorSockets.StreamSessionReactor.RetryPeersWithBufferedMessages() — then has its delivery counter emitted exactly once (ReactorSockets.StreamSessionReactor.EmitDeliveryCounters()), before every Peer's queued retention bytes are flushed exactly once (ReactorSockets.StreamSessionReactor.FlushPendingRetentionWrites()) regardless of how many Send(PeerId, ReadOnlySpan<byte>) calls queued them. Finally, every established Peer's two independent idle timers are enforced in one scan (ReactorSockets.StreamSessionReactor.EnforceIdleTimers()): a Peer from which nothing has been received for ReactorSockets.StreamSessionReactor.PeerSlot.RemoteSendIdleInterval × ResolvedMissedHeartbeats moves to PeerInterrupted, an already-Interrupted Peer instead closes with LingerExpired once its effective Linger has elapsed since the interruption, and every surviving Peer that has written nothing to the wire — including whatever this Frame's own flush just carried — for at least SendIdleInterval sends the same delivery-counter record as a heartbeat, unconditionally and regardless of whether anything was ever received from it. Every accepted connection still waiting for its first handshake record once its deadline has passed is then closed (ReactorSockets.StreamSessionReactor.ExpirePendingAdmissions()). The same scan closes with TransportFailed every Peer this Reactor dialled that has not established one Linger after Connect(IPEndPoint). Once idle timers may have closed an Interrupted Peer on Linger expiry, every Interrupted Peer this Reactor itself dialled is given its re-dial attempt for this Frame (ReactorSockets.StreamSessionReactor.ProcessRedials()) — a schedule derived from the observed Pump interval just recorded above and the effective Linger, never a separate attempt-count knob, so a Peer whose Linger closed it this same Frame is never also given one. Throws InvalidOperationException if called from any thread other than the one that constructed this Reactor, or from inside a Pump already in progress.

Send(PeerId, ReadOnlySpan<byte>)

Frames message as a u32 big-endian length prefix followed by its bytes (ReactorSockets.Session.MessageFramingCodec, ADR 0010) and appends the framed bytes to peer's retention region. Nothing is written to the socket here, ever (write batching) — a successful append only sets this Peer's pending-write marker (ReactorSockets.StreamSessionReactor.PeerSlot.HasPendingRetentionWrite), which the next Pump()'s explicit flush step (ReactorSockets.StreamSessionReactor.FlushPendingRetentionWrites()) drains in a single write carrying everything queued, including whatever was already sitting there. A Send with no following Pump call puts nothing on the wire. Refuses once a Goodbye has passed in either direction — this end's own (ReactorSockets.StreamSessionReactor.PeerSlot.LocalGoodbyeSent) or the far end's arrived and this Peer is already PeerClosing or on its way to PeerClosed (ReactorSockets.StreamSessionReactor.PeerSlot.PendingCloseReasonAfterRetentionDrains) — since a Message queued after a Goodbye is not one the far end has any business receiving. Also refuses a Peer whose handshake has not reached ReactorSockets.StreamSessionReactor.HandshakeState.Established with NotEstablished: flushing that Message would write to a socket whose connect has not resolved, closing the Peer with TransportFailed, or send it before the far end's handshake record has been read. Once the Peer is established, refuses a Message longer than the MaxMessageSize it announced in its Hello (ReactorSockets.StreamSessionReactor.PeerSlot.RemoteMaxMessageSize) with RemoteMessageTooLarge, copying nothing: the far end would close the Session with ProtocolViolation on its length prefix.
