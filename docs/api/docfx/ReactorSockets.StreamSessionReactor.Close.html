Close(PeerId)

Announces this end is ending the Session with peer on purpose: attempts to append a Goodbye control record to whatever this Peer's retention region already holds, so it is the last thing flushed and everything queued before it is delivered first, then forbids any further Send(PeerId, ReadOnlySpan<byte>) to it. If retention has no room for it yet, the attempt is retried on every later Pump (ReactorSockets.StreamSessionReactor.RetryGoodbyeAppends()) until it commits — Close(PeerId) must never leave the far end open indefinitely because the Goodbye it promised was silently dropped, and this end never closes itself locally until its own Goodbye has actually been appended and flushed. The PeerClosed carrying LocalClose is queued once that flush fully drains — immediately, on a later Pump, if nothing was queued when Close(PeerId) was called, or after however many Pumps a short write (or a retention append retry) takes to carry everything already retained plus the Goodbye itself. Idempotent: a stale PeerId, or a Peer already closing, is a no-op — a Peer closing under a caller, or a caller that closes the same Peer twice, is an ordinary race rather than a programmer error.
